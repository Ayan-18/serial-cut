# SerialCuts

SerialCuts - локальное Windows-приложение для поиска осмысленных фрагментов в сериях с русской озвучкой и подготовки вертикальных MP4 для YouTube Shorts / Instagram Reels. MVP не публикует ролики автоматически и не отправляет исходные видео, кадры, аудио или расшифровки во внешние AI-сервисы.

## Состояние репозитория

На старте папка проекта была пустой, без `.git`, `AGENTS.md` и `.openai/hosting.json`. Первый этап создал рабочий каркас: FastAPI backend, SQLite-модели, Alembic-миграцию, импорт папки сезона, fingerprint/dedupe, безопасную обёртку ffprobe, persistent job queue, system-check и минимальную русскую React-панель.

Второй этап добавил media pipeline: выбор русской аудио/субтитровой дорожки, атомарное извлечение mono WAV 16 kHz, создание proxy MP4 с выбранной русской AAC-дорожкой, lazy-интеграцию faster-whisper, lazy-интеграцию PySceneDetect AdaptiveDetector, сохранение transcript word timestamps и scene boundaries, а также stub-компоненты для тестов без GPU и тяжёлых моделей.

Третий-пятый этапы добавили MVP-путь от расшифровки к готовому ролику: локальный llama.cpp HTTP adapter + stub, строгие Pydantic JSON-схемы, карту эпизода, генерацию/валидацию/дедупликацию кандидатов, карточки кандидатов в UI, review, русские SRT/ASS, FFmpeg render 1080x1920, export metadata/cover и Telegram long polling adapter с whitelist и идемпотентными callback-действиями.

Следующий срез добавил первые продуктовые фичи: автоматический режим, локально сохраняемые настройки UI, сезонную очередь с pause/resume/run-next/cancel/retry и улучшенный render с пресетами YouTube Shorts / Instagram Reels, NVENC auto-detect, экспортом без субтитров и опциональным двухпроходным loudnorm.

Текущий продуктовый экран добавляет фоновую очередь, вертикальный предпросмотр выбранного отрывка,
ручной редактор субтитров и кадрирования, локальный поиск лиц, эвристические метки говорящих,
фильтры кандидатов, диагностику моделей, безопасную очистку кэша и галерею готовых экспортов.

Раздел **«Сюжетные видео»** добавляет первый слой для нарезок не из одной серии, а из всего сезона.
Он создаёт сохраняемый монтажный план `StoryArc` из уже найденных кандидатов разных серий: один
Shorts, серию Shorts, видео 2–10 минут или будущий длинный ролик. План можно строить по текстовому
запросу, по персонажу или по общей сюжетной арке; каждый пункт плана ведёт обратно к исходному
кандидату для проверки границ, кадра и субтитров.

Сохранённый `StoryArc` можно отрендерить в один MP4: SerialCuts рендерит каждый фрагмент из своего
исходного файла в единый вертикальный формат, нормализует звук и делает настоящие `xfade` / audio
crossfade-переходы либо обычную склейку. Для арок по персонажу сохраняется черновик текста озвучки;
локальная Qwen может связать части в один текст (если недоступна — текст собирается по шаблону, и
это явно помечено в карточке арки), а локальный TTS создаёт WAV. По умолчанию это
нейросетевой **Silero v4_ru** (живой русский голос диктора, работает на CPU); движок переключается
в настройках на голос Windows (SAPI) или тестовый режим. Голос для арки от лица героя берётся из
карточки персонажа — можно закрепить конкретный голос или оставить авто по полу персонажа; в режиме
нейтрального рассказчика используется голос диктора из настроек. При включённой опции WAV
раскладывается по началам сегментов, проверяется по длительности и смешивается с
оригиналом через sidechain ducking: оригинальный звук становится тише только во время речи
диктора. Доступны режимы `first_person`, `narrator` и `none`; если у StoryArc не выбран персонаж,
режим от первого лица автоматически становится нейтральным диктором. Это синтетический голос, не
voice cloning и не имитация голоса конкретного актёра.

Новый блок **Workflow сезона** добавляет сезонный поиск по кандидатам и транскриптам, ручной
редактор StoryArc-сегментов, StoryArc-render через очередь, fade-переходы между кусками, генератор
сценария будущего видео, черновой пакет публикации и диагностику состояния проекта.

Правки кандидатов и StoryArc версионируются: после изменения границ, кадрирования или порядка старый
рендер получает статус «нужно обновить» и не используется повторно. Ручные сегменты сохраняются при
пересборке, границы внутри речи расширяются до полной реплики, а повтор кандидата не добавляется.
Остановка queued-render завершает активный FFmpeg-процесс и оставляет задачу на паузе. Интерфейс
ставит долгие действия в очередь: отдельный media-анализ, пересоздание кандидатов, auto-export и
StoryArc-render не блокируют HTTP-запрос до завершения тяжёлого FFmpeg/Whisper/LLM шага.
Первоначальные лимиты частей и длительности теперь сохраняются в плане и не сбрасываются после
ручного удаления сегмента и пересборки.

Публикация остаётся полностью локальной. После готового StoryArc UI может собрать проверенный
`publishing.json` с путём к MP4, обложкой, заголовком, описанием, хэштегами и расписанием. Загрузка в
YouTube, Instagram, TikTok или VK выполняется пользователем отдельно; токены платформ не нужны.

Сюжетный режим позволяет сохранить общий контекст сезона и серии, обязательные/исключённые события
и собрать кандидаты как хронологические части одного пересказа. Библиотека персонажей принимает
локальные фотографии, осторожно сопоставляет их с голосовыми кластерами и оставляет имя неизвестным,
если уверенности недостаточно. Все фотографии хранятся только в `data/characters`.

Идентификация персонажей объединяет три локальных сигнала: нейросетевые YuNet/SFace, движение
области рта во время реплики и обучаемый голосовой профиль. Ручная привязка `Говорящий N`
одновременно добавляет подтверждённые образцы голоса персонажу; в следующих сериях приложение может
узнавать его по голосу. Кадрирование сначала ищет подтверждённого активного персонажа, затем
говорящего по губам и только после этого использует крупнейшее лицо как fallback.

Последние срезы добавили: **нейросетевую озвучку StoryArc** (Silero v4_ru на CPU) с голосом на
персонажа или авто по полу; **удаление** сезонов, серий и задач очереди с каскадом по производным
строкам и файлам; **операбельность** — `/api/health` с `boot_id`, просмотр журнала в панели, каталог
локальных моделей с установкой из UI, история правок кандидата с откатом, пакетные действия,
раскадровку кадра, генерируемый `docs/API.md`. Отдельно закрыт класс «тихих отказов»: функция,
которой не хватает модели или внешнего инструмента (трекинг лица без YuNet/SFace, озвучка без Qwen
или без русского голоса Windows, двухпроходный loudnorm), теперь сообщает об этом явно, а не молча
деградирует. Проверка `Host`-заголовка закрывает DNS-rebinding.

## Быстрый старт Windows с реальными моделями

Требуется Python 3.11.x, Node.js 22+ или 24+, FFmpeg/ffprobe и `llama-server` в `PATH`.
PowerShell-команды ниже используют разовый обход Execution Policy и не меняют системную политику.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
winget install --exact --id ggml.llamacpp
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install_models.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_system.ps1
```

`scripts\bootstrap.ps1` проверяет Python 3.11, FFmpeg/ffprobe, Node и `llama-server` с понятными
сообщениями, создаёт `.env` и `.venv`, ставит зависимости, применяет миграции и собирает
frontend. `Start SerialCuts.cmd` запускает его автоматически при первом старте. Прежний
`scripts\setup.ps1` тоже работает.

Если Whisper и Qwen уже установлены, отдельно поставить небольшие модели лиц можно командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install_identity_models.ps1
```

Скрипт скачивает около 39 МБ из официального OpenCV Zoo, проверяет SHA-256 и сохраняет модели в
`data/models/face`. Фотографии, видео, аудио и рассчитанные признаки никуда не отправляются.

Чтобы включить реальные адаптеры, задайте в `.env`:

```env
SERIALCUTS_ASR_ADAPTER=faster-whisper
SERIALCUTS_ASR_MODEL_NAME=./data/models/faster-whisper-small
SERIALCUTS_ASR_DEVICE=cpu
SERIALCUTS_LLM_ADAPTER=llama-cpp-http
```

Запуск приложения и локальной Qwen одной командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_local.ps1
```

Откройте `http://127.0.0.1:8090`. Модель Qwen запускается скрыто только на `127.0.0.1` и
останавливается вместе с приложением. `run_local.ps1` работает как супервизор: каждые 15 секунд
проверяет `/health` локальной Qwen и перезапускает её, если она перестала отвечать, пока приложение
работает. Логи пишутся в `data/logs/serialcuts.log` с ротацией; уровень управляется через
`SERIALCUTS_LOG_LEVEL`. Вариант без моделей для быстрой проверки интерфейса остаётся доступен через
адаптеры `stub` и `scripts/run.ps1`.

Можно также дважды щёлкнуть `Start SerialCuts.cmd`. Скрипт `scripts/create_shortcut.ps1` создаёт
ярлык `SerialCuts` на рабочем столе; на настроенном компьютере он уже создан.

## Quality Benchmark

Для проверки качества алгоритмов без тяжёлых видео есть лёгкие JSON-сценарии в `tests/quality`.
Они прогоняют candidate scoring, boundary adjustment и dedupe на тестовых transcript/scenes и
показывают метрики:

```powershell
.\scripts\quality_check.ps1
```

Отчёт включает `Overall`, `Candidate quality`, `Boundary quality`, coverage ожидаемых сцен,
precision, duplicate rate и invalid clips. Это базовый измеритель перед изменениями логики выбора
моментов.

Дополнительно `tests/test_media_smoke.py` генерирует короткие тестовые H.264/AAC-файлы, рендерит
обычный вертикальный MP4 и multi-source StoryArc MP4, затем проверяет потоки через ffprobe. Реальные
серии для этой проверки не нужны.

## Операционные Возможности

Последний срез добавляет удобство эксплуатации без изменения launcher:

- `GET /api/health` возвращает версию, короткий git-commit, `boot_id` процесса, отпечаток
  локального токена, аптайм, ревизию БД и состояние очереди; фронтенд отслеживает `boot_id` и
  предлагает перезагрузить страницу после перезапуска бэкенда. Есть `GET /api/version`.
- `GET /api/logs` отдаёт хвост ротируемого журнала с фильтром по уровню и тексту; в панели есть
  просмотр журнала с автообновлением.
- `GET /api/model-catalog` показывает локальные модели (ASR, Qwen, лица, озвучка Silero): размер,
  папку, статус установки и точную команду. Небольшие модели (лица, Silero ~60 МБ) скачиваются
  прямо из панели после подтверждения: `POST /api/model-catalog/{key}/install` запускает загрузку
  в фоне, а `GET /api/model-catalog/{key}/install-progress` отдаёт байтовый прогресс (панель рисует
  полосу). Одновременно ставится только одна модель. Whisper и Qwen по-прежнему ставятся скриптом.
  Для Silero нужен опциональный пакет `torch`: `pip install -e ".[tts]"`.
- Правки кандидата версионируются как снимки: `GET /api/candidates/{id}/history` и
  `POST /api/candidates/{id}/history/{snapshot_id}/restore` откатывают границы, кадр и субтитры;
  сам откат тоже сохраняется.
- Пакетные действия: `POST /api/episodes/{id}/candidates/batch-review` и
  `POST /api/candidates/batch-render-job` принимают/отклоняют/ставят в рендер сразу несколько
  кандидатов и сообщают причину пропуска для каждого.
- `GET /api/candidates/{id}/keyframes` собирает полосу миниатюр по кандидату одним проходом
  FFmpeg (кэш по ревизии правок); в редакторе кадра клик по миниатюре перематывает превью.
- Импорт сезона возвращает число просканированных файлов и список нечитаемых (заблокированных
  антивирусом/проводником) — импорт не прерывается на одном файле.
- `GET /api/events` — SSE-поток очереди и задач: фронтенд подписывается на него вместо опроса
  `GET /api/jobs` каждые 2.5 с, поэтому прогресс обновляется сразу и без рывков. Если поток
  недоступен, UI автоматически откатывается на короткий опрос.
- `GET /api/system-check` добавил необязательные проверки Node, `llama-server`, запуска вне
  `.venv` и поддержки длинных путей Windows.
- `DELETE /api/episodes/{id}`, `DELETE /api/seasons/{id}`, `DELETE /api/jobs/{id}` убирают ошибочный
  импорт или мёртвую задачу вместе со всеми производными строками и файлами (только внутри
  cache/output/characters); удаление серии подчищает сегменты StoryArc, а удаление заблокировано
  `409`, пока по серии/задаче идёт работа. В панели — красная корзина у сезонов, серий и
  завершённых задач.
- Отказ вместо тихой деградации: если этап конвейера отработал с оговоркой (не собралась
  кластеризация говорящих, двухпроходный loudnorm не дал результат), задача завершается с видимой
  пометкой в очереди и в полосе качества серии. `identify-characters` различает «нет меток
  Говорящий N» и «нет моделей YuNet/SFace». Windows-озвучка падает с ошибкой, если в системе нет
  русского голоса, а не читает текст английским.

Полный список эндпоинтов генерируется из приложения: `docs/API.md` и `docs/openapi.json`
(`.\.venv\Scripts\python.exe scripts\dump_openapi.py`).

## Безопасность исходников

Импорт открывает видео только для чтения. Оригинальные серии не копируются целиком, не изменяются и не удаляются. Кнопка очистки в UI работает только в выделенной папке с маркером `.serialcuts-cache`, проверяет защищённые пути, блокируется при незавершённых задачах и требует подтверждения. Готовые ролики и исходные серии она не затрагивает. HTTP API принимает запросы только с этого компьютера; запуск на `0.0.0.0` запрещён. Заголовок `Host` проверяется по белому списку (`localhost`, `127.0.0.1`, `::1` и loopback-IP на любом порту) — это закрывает DNS-rebinding, когда домен атакующего резолвится в `127.0.0.1`. Unsafe-запросы `POST` / `PUT` / `PATCH` / `DELETE` дополнительно требуют одноразовый локальный `X-SerialCuts-Token`, который штатный frontend получает сам через same-origin `GET /api/security-token`. Отдача готовых файлов (`/api/exports/{id}/file`, обложки, фото персонажей, кадры) проходит через `resolve_within`: путь из БД не может выйти за пределы output/cache.

## Fingerprint

Для многогигабайтных файлов полный SHA-256 слишком дорог на каждом импорте. В MVP используется устойчивый fingerprint из размера файла, `mtime_ns` и SHA-256 выборок: начало, середина и конец файла по 1 MiB. Это быстро выявляет дубликаты в обычном локальном сезоне. Если файл был перекодирован или изменён без смены видимых метаданных, fingerprint может измениться; это приемлемо для MVP и задокументировано как компромисс между скоростью и надёжностью.

## Media Pipeline MVP

По умолчанию `SERIALCUTS_ASR_ADAPTER=stub`, чтобы можно было проверить конвейер без скачивания модели. Для реального распознавания:

```env
SERIALCUTS_ASR_ADAPTER=faster-whisper
SERIALCUTS_ASR_MODEL_NAME=./data/models/faster-whisper-small
SERIALCUTS_ASR_DEVICE=cpu
SERIALCUTS_ASR_COMPUTE_TYPE=int8
SERIALCUTS_ASR_FALLBACK_COMPUTE_TYPE=int8
```

FFmpeg-команды строятся только как массив аргументов и пишут во временный файл рядом с целевым, затем атомарно переименовывают результат. Исходное видео передаётся FFmpeg как входной файл и не изменяется.

## LLM и кандидаты

По умолчанию `SERIALCUTS_LLM_ADAPTER=stub`. Для локального llama.cpp:

```env
SERIALCUTS_LLM_ADAPTER=llama-cpp-http
SERIALCUTS_LLM_BASE_URL=http://127.0.0.1:8081
SERIALCUTS_LLM_MODEL_HINT=Qwen3-4B-GGUF-Q4_K_M
```

Адаптер использует локальный endpoint `/v1/chat/completions` с JSON Schema. Адрес проверяется при запуске и
в настройках: разрешены только `localhost` и loopback-IP, поэтому расшифровка не может уйти на удалённый
LLM из-за ошибки в `.env`. Расшифровка делится
на три временные части, чтобы кандидаты искались по всему эпизоду, а не только в начале. Ответы
валидируются через Pydantic, короткие границы расширяются до настроенного минимума и затем
корректируются по словам/сценам.

Доступны два режима: независимые `Лучшие моменты` и хронологический `Сюжет серии`. Во втором режиме
локальная Qwen получает пользовательский контекст и сюжетную карту, выбирает необходимые моменты
из последовательных частей расшифровки и сохраняет номер/роль каждой части. После этого границы
привязываются только к целым репликам: жёсткий лимит длительности больше не должен обрезать начатую
фразу, а сомнительная граница получает явное предупреждение.

## Auto Mode И Очередь

В панели можно поставить серию или весь сезон в очередь обычным режимом либо `Auto`. Фоновый worker
сам берёт следующую задачу, восстанавливает прерванные задачи после запуска и показывает этап,
прогресс, текущую операцию, ошибку и ETA. ETA считается по реальной истории времени отдельно для каждого типа
задачи и учитывает уже выполненную долю. Очередь можно поставить на паузу, безопасно остановить задачу или повторить
ошибочную. `run-next` оставлен для ручной диагностики и тестов. Рендер также идёт через очередь,
поэтому во время него интерфейс остаётся доступен.

Тяжёлые операции выполняются строго по одной даже при случайном запуске двух процессов: job атомарно
получает worker-id, lease и heartbeat, а просроченный lease безопасно восстанавливается. Если серия уже стоит в очереди, ручные кнопки анализа
для неё отключаются, а API возвращает понятный конфликт `409` вместо ошибки SQLite. Whisper, Qwen,
поиск сцен и FFmpeg не удерживают транзакцию базы во время вычислений; SQLite работает в WAL-режиме
с ожиданием кратковременно занятой записи.

Каждый повторный рендер создаёт новую версию MP4/ASS/JPG/JSON и новую запись экспорта. Полный
render fingerprint учитывает исходник и аудиодорожку, границы, crop, текст и стиль субтитров,
preset/loudnorm, переходы и озвучку. Поэтому уже собранный publishing plan не меняется вслед за
более новым рендером.

## Render

Доступны пресеты:

- `youtube_shorts`: 1080x1920, H.264, AAC 160k.
- `instagram_reels`: 1080x1920, H.264, AAC 192k.

NVENC можно включить вручную или оставить auto-detect в backend. Экспорт без субтитров доступен отдельной кнопкой. Двухпроходный loudnorm включается настройкой `render_loudnorm_two_pass`; если анализ не дал валидный JSON, используется обычный безопасный loudnorm-фильтр — и в этом случае задача рендера завершается с видимой пометкой в очереди, а не молча.

Субтитры синхронизируются по таймкодам распознанных слов, выводятся максимум в две строки и
рассчитаны на кадр 1080x1920. Текст и имя шрифта экранируются перед созданием ASS, чтобы текст из ASR или ручного
редактора не мог вставить команду стиля. Размер шрифта регулируется в панели; значение по умолчанию — 48.
Повторное нажатие кнопки рендера пересобирает существующий производный клип. Если NVENC установлен,
но драйвер не поддерживает нужную FFmpeg API, рендер автоматически повторяется через CPU `libx264`.

Редактор кандидата проигрывает только выбранный временной диапазон, показывает субтитры поверх
вертикального предпросмотра и позволяет менять текст, тайминги и подпись говорящего. Кадр можно
сместить, увеличить или автоматически центрировать по найденным лицам. Карточка персонажа принимает
сразу несколько фотографий и позволяет добавлять или удалять отдельные ракурсы. Ручная привязка
голоса создаёт локальный спектральный voiceprint; автоматическое назначение требует высокого порога
и не сохраняет неоднозначные совпадения. Результаты рекомендуется проверить перед финальным рендером.

После `Найти лица` YuNet находит все лица на **исходном** файле (не на proxy — мелкие лица так не
теряются), SFace сопоставляет их с фотографиями, а анализ изменения области рта выбирает активного
говорящего там, где имя ещё неизвестно. Сохраняется сглаженная временная траектория, и FFmpeg
плавно перемещает crop по ходу ролика; трекинг работает построчно за подтверждённым говорящим,
затем за движением губ, и только потом за крупнейшим лицом. Траектория переживает подкрутку
смещения/масштаба и сбрасывается только при смене границ или уходе из режима «По лицам». Персонажа
можно выбрать из списка в каждой строке субтитров; настройка `Показывать имя персонажа` добавляет
подтверждённое имя над текстом в готовом видео.

Кадрирование по лицам и идентификация персонажей требуют локальных весов **YuNet + SFace**
(`data/models/face`, ~39 МБ, `scripts/install_identity_models.ps1` или кнопка «Скачать» в разделе
«Локальные модели»). Без них `POST /api/candidates/{id}/auto-crop` возвращает понятный `422` с
инструкцией по установке, а не молча центрирует кадр. На OpenCV 5 резервного Haar-детектора больше
нет. Обложка ролика выбирается по резкости, экспозиции и (при наличии моделей) по лицу в кадре.

## Telegram

Мобильный пульт к запущенному локально приложению. Бот работает через long polling
(без webhook/VPS) и требует whitelist:

```env
SERIALCUTS_TELEGRAM_BOT_TOKEN=<telegram_bot_token>
SERIALCUTS_TELEGRAM_ALLOWED_USER_IDS=111111111,222222222
```

Запуск отдельным процессом (приложение должно быть уже запущено, а фоновая очередь —
включена, иначе задачи будут просто стоять):

```powershell
.\scripts\run_telegram.ps1
```

Команды:

- `/status` — состояние очереди.
- `/episodes` — сезоны и серии со ссылками `/candidates <id>`.
- `/candidates <id серии>` — топ-8 кандидатов с кнопками.
- `/preview <id кандидата>` — карточка кандидата с обложкой.
- `/pause`, `/resume` — управление очередью.

Кнопки: **Принять** / **Отклонить** мгновенны; **Рендер** ставит задачу в общую очередь
(FFmpeg не запускается внутри бота). Все три идемпотентны — повторное нажатие возвращает
сохранённый результат. Когда задача завершается, воркер сам присылает в whitelist готовый
MP4 (или сообщение с путём, если файл больше 50 МБ) либо текст ошибки.

## Cache и модели

Модели скачиваются только после явного подтверждения командой `scripts/install_models.ps1` и
хранятся в `data/models` (около 3 GB). В разделе «Готовность системы» виден статус обоих локальных
адаптеров. Cache можно очистить там же после подтверждения; готовые ролики лежат отдельно в
`SERIALCUTS_OUTPUT_DIR`. Не удаляйте папки с исходными сериями.
